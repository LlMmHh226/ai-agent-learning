# 从案例定义到审核与复测

[本组课程](README.md)

1. 固定正式入口、模型、代码与知识版本，先定义任务成功条件。
2. 在cases/agent_baseline.json中选案例，核对问题、参数、工具策略和必要事实。
3. 使用 `python -m learning.evaluation.step_02_run_first_case --list-cases` 列出案例，用 `--case-id ID --show-case` 预览，不调用模型。
4. 确认后用 `--case-id ID --run` 执行一条；程序记录SDK请求、工具轨迹、HTTP、耗时与源码hash。报告也记录订单与知识后端，防止混淆demo/ngram和postgres/pgvector结果。
5. 先查机械结果：工具名、参数、调用次序与业务字段。再由人工核对事实、条件、对象归属、否定和引用。
6. 保留失败报告，明确失败发生在数据、检索、输入组装还是模型生成；只改与失败相关的最小部分。
7. 用原题原标准复测，再用未参与调优的留出题验证；不要把一次复测成功写成整体成功率。

required要求实际调用；none要求不调用；optional允许正确重查或有可信历史证据的复述。optional不是跳过检查。显式要求“重查最新状态”应与普通复述区别处理。

运行器的patch包装调用原SDK后原样返回，实际结果仍来自真实模型；离线测试才使用模拟响应。两者都要根据实现判断，不能仅看到patch就认定模型是假的。

语义审核默认pending，不因关键词出现自动通过。案例数据是九条教学场景，当前公开版不附带维护者个人报告，也不宣称完成了一套统一环境的综合效果验收。
