追踪端口与卷。对照具体输入解释每个参数从哪里来、返回值交给谁以及失败发生在哪一层。

## 前置知识

先阅读 [镜像与容器](step_02_image_container.md)。 使用环境：Docker Engine。所有Python命令在仓库根目录运行；安装见 [运行说明](../../docs/setup.md)。

## 文件职责

- [核心文件](../postgresql/compose.yaml)：按本课数据流查找对应定义。

## 具体输入与执行过程

```text
根.env
→ compose.yaml
→ postgres容器
→ 本机25432转容器5432
```

先找到入口，再标出关键函数的参数与返回点。学习脚本是分步实现；`app`中的整合版可能同时支持演示与数据库后端，观察时记下当前配置，避免混用结果。

## 运行与预期结果

**访问范围：首次下载镜像需要联网；不请求模型。**

```console
docker compose --env-file .env -f learning/postgresql/compose.yaml up -d --wait
```

应观察到：独立命名数据卷保留本教程数据库。



先按 [数据库安装](../../docs/database.md)填写根.env的POSTGRES字段。Compose只转发数据库所需字段；公开版默认25432端口与独立数据卷，以免占用原学习服务。

## 常见错误

- 导入失败：确认位于仓库根目录，并使用本课对应的独立环境。
- 运行结果与预期不同：先检查后端配置、前置服务及当前代码版本，再判断是否属于模型行为差异。
- 不必然；数据在命名卷中，但显式down -v会删除卷，需先确认数据可丢弃。
