# 多 Agent 23D：一次路由与参数校验

## 学习目标

把「模型提出走哪条路线」与「后端验证并分派」分开；辨认入口路由和执行中主管的区别。

## 前置知识

看过 [23C 的固定顺序](step_23c_two_agents.md)，理解 JSON schema 或 Pydantic 的基本校验。

## 文件职责

[路由器示例](step_23d_router.py) 用 `Decision` 限制路线枚举，并检查候选订单号是否与问题中的唯一五位编号一致。`dispatch()` 打印路线，本课不执行角色或工具。

## 具体输入与执行过程

「看看订单10001能不能退」 → 固定候选 `{route: order_then_returns, order_id: "10001"}` → `model_validate` 与编号核对 → 订单 → 售后。对「帮我查物流」即使候选自行填了 `10001`，也降级为追问。输入有两个不同编号也先追问。

## 运行与预期结果

```console
python -m learning.multi_agent.step_23d_router
```

观察订单单独处理、订单串接售后与三条追问分支。输入、路由建议都固定，只验证后端校验；没有真实模型或数据库调用。

## 常见错误

- 把模型返回合法 JSON 等同于选对业务路线：结构校验不能证明订单或意图真实。
- 把路由分派称为主管循环：这里一次选择起点；主管会在工作节点返回后基于新状态再选下一步。

## 自测与参考答案

明确写了两个订单号的请求，怎样扩展流程才不容易串单？

<details>
<summary>参考答案</summary>

当前先澄清。要支持多订单，先为每个经验证的 ID 建立独立任务，按订单隔离工具结果、待补字段与汇总证据；不能用最后一个订单覆盖前一个。
