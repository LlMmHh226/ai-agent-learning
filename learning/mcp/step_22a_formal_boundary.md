# MCP 22A：先确定工具执行边界

## 学习目标

把「模型给出的工具参数」和「如何执行查询」分开；让本地函数与 MCP 网关返回同样的业务字段。

## 前置知识

了解 [21C 的工具适配](step_21c_tool_adapter.md) 和 [21D 的错误分层](step_21d_error_layers.md)。

## 文件职责

[22A 脚本](step_22a_formal_boundary.py) 严格校验参数，再根据是否注入网关选择执行方式；[样例订单](../../app/repositories/demo_orders.py) 提供固定事实。

## 具体输入与执行过程

工具参数字符串 `{"order_id":"10001"}` → `json.loads` → 校验只有 `order_id` 且是五位字符串 → 本地订单函数或注入的网关 → 得到含 `found` 的业务结果。数组、整数订单号、多余字段或损坏的 JSON 在执行前被拒绝。

## 运行与预期结果

```console
python -m learning.mcp.step_22a_formal_boundary
```

输出两条执行路径一致的样例结果，并打印四种参数拒绝。两条路径都在本进程执行；本课没有 MCP 子进程、业务数据库或外部模型。

## 常见错误

- 用 `str()` 补救模型给的数字订单号：这会改变输入契约，而且编号的前导零可能已丢失。
- 把所有失败都包装成 `found:false`：参数错误、调用错误和正常查无记录要分开。
